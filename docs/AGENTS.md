# Agent Onboarding Guide

> This is the stable onboarding guide for AI collaborators working on Focus-tui.
> The `AGENTS.md` file in the repository root is auto-generated by Focus-tui for
> per-session runtime context and should not be edited manually.

## Project Identity

**Focus-tui** is a terminal-native execution workbench for parallel agent
development. It lets operators run multiple coding agents across multiple git
worktrees without losing control of context, dependencies, and handoff.

Core philosophy:

- **Agent-neutral** — Focus-tui does not lock you into a single model or vendor.
- **Operator sovereign** — humans steer at the phase level; agents schedule their
  own steps within a shared execution system.
- **Specs injected, not remembered** — context and conventions live in files,
  not in conversational memory.

## Quick Reference

### Tech Stack

- **Go** — primary implementation language (see `go.mod` for the exact version).
- **SQLite** — default local store for tasks, sessions, and worktree context.
- **Embedded PostgreSQL** — optional store backend via `FOCUS_STORE=postgresql`.
- **Bubble Tea** — TUI framework.
- **MCP / A2A** — agent integration protocols.
- **Trellis** — optional integration for durable specs, PRDs, workflow state,
  and handoff journals.

### Essential Commands

```bash
# Build the CLI
go build ./cmd/focus

# Run the TUI directly
go run ./cmd/focus

# Run all tests
go test ./...

# Prepare demo data
scripts/prepare-demo-data.sh
```

## Project Structure

```
cmd/focus/        # CLI entry point
internal/         # Core implementation; business logic lives here
  app/            # TUI application layer
  store/          # Database and event store
  agents/         # Agent discovery, registry, and drivers
  trellis/        # Trellis integration bridge
  plugins/        # Git, editor, and other plugins
  ...
docs/             # ADRs, architecture docs, release process
scripts/          # Helper scripts
.focus/           # Runtime state (gitignored; never commit)
.trellis/         # Trellis workspace (gitignored; do not edit directly)
```

Keep implementation code under `internal/`. Do not add business logic at the
repository root.

## Development Workflow

1. **Use feature branches.** Do not commit directly to `master`.
2. **Use Trellis tasks when available.**
   ```bash
   python3 ./.trellis/scripts/task.py create "<title>"
   python3 ./.trellis/scripts/task.py start <slug>
   # ... do the work ...
   python3 ./.trellis/scripts/task.py finish
   ```
3. **Follow commit conventions.** Use Sentry-style conventional commits. The
   project provides a `commit` skill for this.
4. **Run the quality gate before claiming work is complete:**
   - `go test ./...`
   - `go vet ./...`
   - Cross-layer consistency checks (see the thinking guides below).
5. **Persist learnings.** When you discover a new pattern or fix a bug class,
   update the relevant Trellis spec or ADR so the next agent benefits.

## Code Conventions

- Follow standard Go style and the patterns already present in the codebase.
- Wrap errors with context:
  ```go
  return fmt.Errorf("open database: %w", err)
  ```
- Write tests for core logic. Reference `internal/app/*_test.go` for TUI
  testing patterns.
- **Search first.** Before adding new code or changing a value, grep the
  codebase for existing patterns. See
  [`.trellis/spec/guides/code-reuse-thinking-guide.md`](../.trellis/spec/guides/code-reuse-thinking-guide.md).
- **Think cross-layer.** For changes spanning multiple layers, read
  [`.trellis/spec/guides/cross-layer-thinking-guide.md`](../.trellis/spec/guides/cross-layer-thinking-guide.md)
  first.

## Agent Collaboration Rules

- Read the relevant ADRs and architecture docs before modifying core behavior.
- Make small, independently reviewable commits.
- Do not modify gitignored generated files, including:
  - `.focus/` — runtime state and legacy local data.
  - `.trellis/` — generated Trellis workspace.
  - root `AGENTS.md` — auto-generated session context.
  - build binaries (`focus`, `focus-tui`, `focus-dev`).
- Communicate with the user in the same language they use. Write project
  documentation in English.
- When a new convention or pitfall emerges, capture it in a spec or thinking
  guide rather than leaving it in chat history.

## Common Pitfalls

- **Cross-layer changes that only touch one layer.** If a data format or
  contract changes, update every layer that consumes it.
- **Committing local runtime state.** `.focus/` and `.trellis/` are gitignored
  for a reason; never force-add them.
- **Force-pushing to `master`.** Use feature branches and normal pushes.
- **Swallowing errors.** In Go, always handle or propagate errors explicitly.
- **Duplicating code.** Search first, extract shared helpers, and follow existing
  patterns.
