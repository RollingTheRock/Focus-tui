# Design: Project-Level Agent Onboarding Guide

## Objective

Establish a stable, version-controlled onboarding document at `docs/AGENTS.md` that every AI collaborator reads before working on Focus-tui. The guide sets the project's collaboration tradition: how agents should understand the codebase, run it, modify it, and hand off work.

The root `AGENTS.md` remains auto-generated by Focus-tui for per-session runtime context (branch, available MCP tools, etc.) and stays gitignored. The new `docs/AGENTS.md` is hand-written and tracked.

## Decision Log

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Location | `docs/AGENTS.md` | Root `AGENTS.md` is already reserved for Focus-tui runtime context. `docs/` is version-controlled and closer to other project documentation. |
| Language | English | Aligns with `README.md` and makes the guide accessible across AI platforms and international collaborators. |
| Scope | Onboarding + workflow charter | A pure quick-start is too thin; a full handbook is too heavy to maintain. A charter covers "how to get started" plus "how to behave". |
| Relationship to Trellis specs | Complementary | `.trellis/spec/` holds dynamic, detailed coding guidelines injected by Trellis. `docs/AGENTS.md` is the stable map that points agents to those guidelines. |

## Content Structure

The document is organized so an agent can read it top-to-bottom in a few minutes and know where to go next.

### 1. Project Identity

One paragraph answering: what is Focus-tui, why does it exist, and what is its core philosophy? Reference the tagline and "agent-neutral, operator sovereign" principle from `README.md`.

### 2. Quick Reference

- **Tech stack**: Go, SQLite / embedded PostgreSQL, Bubble Tea (TUI), MCP, A2A, optional Trellis.
- **Essential commands**:
  - `go build ./cmd/focus`
  - `go test ./...`
  - `go run ./cmd/focus`
  - `scripts/prepare-demo-data.sh`
- **Quick links**: README, ADR index, architecture docs, Trellis guides.

### 3. Project Structure

Map the top-level directories:

- `cmd/focus/` — CLI entry point.
- `internal/` — core implementation; business logic lives here, not at the repository root.
- `docs/` — ADRs, architecture, release process.
- `scripts/` — helper scripts.
- `.trellis/` — generated/local Trellis workspace (gitignored; do not edit directly).
- `.focus/` — runtime state and legacy local data (gitignored; never commit).

### 4. Development Workflow

- Use the Trellis task system when available: `python3 ./.trellis/scripts/task.py create/start/finish`.
- Never commit directly to `master`; use feature branches.
- Follow the project's commit conventions (Sentry-style, conventional commits).
- Run the quality gate before claiming work complete: tests, lint, and cross-layer checks.
- Persist decisions and learnings in specs/ADRs, not just in chat history.

### 5. Code Conventions

- Follow standard Go style and existing project patterns.
- Wrap errors with context: `fmt.Errorf("...: %w", err)`.
- Write tests for core logic; reference `internal/app/*_test.go` for TUI testing patterns.
- Before adding new code or changing a value, search the codebase for existing patterns (see `.trellis/spec/guides/code-reuse-thinking-guide.md`).
- For cross-layer changes, read `.trellis/spec/guides/cross-layer-thinking-guide.md` first.

### 6. Agent Collaboration Rules

- Read the relevant ADRs and architecture docs before modifying core behavior.
- Make small, independently reviewable commits.
- Do not modify gitignored generated files (`.focus/`, `.trellis/`, root `AGENTS.md`, build binaries).
- When a new pattern or bug class is discovered, update the appropriate Trellis spec or thinking guide.
- Communicate in the same language as the user for conversational work; write project documentation in English.

### 7. Common Pitfalls

- Cross-layer changes that only touch one layer.
- Committing local runtime state from `.focus/`.
- Force-pushing to `master`.
- Ignoring Go error handling or swallowing errors.

### 8. Where to Look Next

- `docs/adr/` — architectural decisions.
- `docs/architecture/` — system architecture and protocol docs.
- `.trellis/spec/guides/` — code reuse and cross-layer thinking guides.
- `README.md` — user-facing quick start.

## Success Criteria

- A new AI collaborator can read `docs/AGENTS.md` and know how to build, test, and modify the project without asking.
- The guide does not duplicate `README.md`, ADRs, or Trellis specs; it links to them.
- The file is tracked in git and evolves with the project.

## Out of Scope

- Replacing or duplicating `.trellis/spec/` content.
- Platform-specific agent prompts (Claude, Kimi, etc.) — those live in their respective IDE adapter configs.
- Detailed API or TUI component documentation — those belong in code comments or dedicated docs.

## Future Work

- After the guide is adopted, add a short checklist at the top for agents to self-verify they have read it.
- Consider translating key sections to Chinese if the primary contributor base shifts.
